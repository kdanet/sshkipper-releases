A native SSH manager for macOS. It fills in keys, passwords and TOTP codes at every bastion and keeps the terminal, services, databases, files, tunnels, web consoles, remote desktops and automations of all your servers in one window. The AI agent helps you dig in — and does nothing dangerous without your “yes”. Missing something? Add it with an extension: the SDK is open and free (MIT).

01extensionExtensions and modules

Need a feature? Ask your agent to build it for you

SSHKipper grows with extensions — and anyone can write one. An extension adds what the app doesn’t have: a database engine, a storage, servers from a cloud’s API, tree items of your own with their own screen. A module is the simplest extension: one server service, often just sh scripts. The SDK is open and free (MIT): write it yourself or hand it to Claude Code or Codex.

02keyBastions and 2FA

A server behind two bastions — in one double-click

Normally that’s ssh -J, a password and a code from your phone at every bastion (jump host). In SSHKipper, keys, passwords and TOTP secrets live in an encrypted document, and the app fills them in at every hop. An ssh your own script starts gets them too — with ⌘⏎.

  • account_treeBastion through bastionA chain of any length opens with a double-click.
  • swap_horizSOCKS5 and HTTP proxiesWhen the first bastion is reachable only through a proxy.
  • verified_userTOTP from anythingA base32 secret, an otpauth:// link, a Google Authenticator export or a QR code. Push and hardware-key 2FA still ask you.
  • descriptionImport ~/.ssh/configProxyJump turns into bastions, port forwards into tunnels.
  • Tailscale and local networkMachines on your network appear in the tree on their own once you add a Tailscale or Local network source.
  • lanRoute profilesTailscale, an office address or another bastion — when the main way is down.
  • targetThe route as you sign inThis Mac, the proxy, each bastion and the server light up as the login passes them — and you see where it stopped.
  • lanOne sign-in per server — and per bastionTabs, splits, files, Docker and databases of a server share one connection, and servers behind one bastion share its connection — its 2FA comes once.
  • keyHost keys under controlIts own known_hosts: if a host key changes, you get a warning, not a silent sign-in.
  • hubRoute diagramHow this Mac reaches a server: bastions, proxies, keys and codes, drawn from the document.
  • touch_appWhen you pressBy default nothing is typed by itself: “Insert code” or ⌘⏎ puts the code straight into the terminal, not via the clipboard. For a server you trust, turn on “Type by itself after checking ssh”.
  • terminalIn any terminalThis Mac’s terminal and SSH tabs alike: the server is found by user and address — any profile of a connection too.
  • key_verticalKey passphrases tooOnce, checked against the key file — then kept in the encrypted document; the key is recognised by its fingerprint.

04auto_awesomeAI agent

The agent digs into the server itself — and asks before anything dangerous

It reads logs, load and containers on its own. It never gets the document’s passwords and keys: they are masked in everything it reads, and secret files like .env open only after your “yes”. What it may do without asking is up to you: four access levels, as in Codex — per server and folder. You pick the model, too.

  • Claude APIPick the model and reasoning depth right in the chat.
  • OpenAIGPT over the API, or any OpenAI-compatible service.
  • DeepSeekDeepSeek models over the API.
  • Ollama · LM StudioA model on this Mac: nothing leaves for the cloud.
  • Claude CodeYour subscription and your agent; web search if you like.
  • CodexOpenAI’s agent in the same panel, with web search too.
  • CursorCursor’s agent answers in the same panel.
  • hubOther agentsGemini CLI, Goose, Hermes, pi over the Agent Client Protocol. Servers still go through SSHKipper’s levels; their own tools on this Mac are theirs.
  • visibilitySecrets are masked before sendingThe document’s passwords and keys, and tokens of known formats, become [REDACTED] before anything goes to a model; .env, keys and shell history need your “yes”. Claude Code and Codex get your Mac’s shell and files only at “Full access”.
  • verified_userA plan in one cardSeveral steps, each with a verdict and a rollback. “Allow this command until the session ends” if you want.
  • historyA chat keeps its serverA chat works with the server it started on: no session — “offline” and “Connect”. History is encrypted with the document key.
  • folderAgent foldersAttach a folder of knowledge to a server — AGENTS.md, skills, notes. The agent reads it on its own and writes only after your “yes”.
  • terminalCommands as a list or a terminalThe block under the terminal shows the agent’s commands with output and exit code; they are kept per server with the chat history.
  • lock_openClaude Code and Codex without limitsIf you like — your skills, plugins and MCP, as in your own terminal. Servers still go through SSHKipper’s levels.

05databaseDatabases

A database client — right behind your bastions

Six engines, editable tables, a query editor and AI that turns words into SQL. Databases open through the same chain as the terminal — no ssh -L, no manual tunnels.

  • MySQL · MariaDBEditable tables, structure, DDL and a relationship map.
  • PostgreSQLPlus partitions, sequences and functions.
  • ClickHousePartitions and compression per table.
  • Redis · ValkeyKeys with TTL, memory by prefix and a console.
  • MongoDBDocuments as a table or a tree, aggregations.
  • SQLiteA file on a server (needs python3 there, not sqlite3) or on this Mac; read-only by default.
  • shieldProduction stays safeOn a Production database every change opens a window with the full SQL and “Check with AI”, on a normal one only irreversible ones; read-only forbids changes altogether.
  • visibilityThe model doesn’t see your dataThe AI filter and “Compose” get only the columns and schema, never table rows.
  • auto_awesomeThe agent plays by the rulesThe AI agent reads the schema and runs queries by the database’s mode and its own level; password tables are always refused.
  • monitoringProcesses, and a Stop that stopsWho is connected and what runs: cancel a query or close a connection, with the exact statement in the question. Stop in the editor tells you whether the server took the cancel.
  • downloadA whole tableExport to CSV, JSON or SQL INSERT, page by page — memory stays flat. A SELECT from one table with its key edits like the table itself.

10shieldSecurity

Your keys stay yours

Passwords, keys and 2FA secrets live in one encrypted file on this Mac. The developer has no copy, no account and no telemetry: SSH goes to your servers, AI straight to the provider, and the document can lock itself. Only an automation you let run on a server with secrets puts them there, in 0600 files.

  • lockEncryptionThe whole document — Argon2id and XChaCha20-Poly1305.
  • fingerprintTouch IDA copy of the document key is guarded by this Mac’s Secure Enclave.
  • keyRecovery keyForgot the password? The recovery key opens the document and lets you set a new one.
  • scheduleAuto-lockOn screen lock, sleep or idle — set per document.
  • keyboardSecure inputTurn on Secure keyboard entry, and while the terminal takes input other apps can’t intercept keystrokes.
  • dnsHost keysIts own known_hosts: a changed key gets a warning, not a silent sign-in.
  • visibility_offMasked secretsThe document’s passwords and tokens of known formats are hidden in session logs and before anything goes to a model.
  • historyBackupsEncrypted copies of earlier versions: the last five, one per hour for a day, one per day for a week; not in Time Machine.
  • keyNo passwords in psssh gets passwords and codes through its own channel, databases through stdin: never in arguments or the environment.
  • descriptionA shared document asks firstCommands on this Mac, reverse tunnels and auto-start from a document someone sent you wait for your “yes”.
  • visibility_offNo telemetryNo analytics, no automatic crash reports: the app never tells the developer what you do or where.
